# 薄肌｜AI 对话式饮食教练

面向减脂、增肌和体型管理人群的个人项目。用户通过文字、餐食照片或浏览器语音转写描述饮食，AI 负责理解和估算，系统更新营养进度，并给出下一餐建议。

[在线体验](https://boji-food-coach.vercel.app) · [产品 PRD](./产品设计文档.md) · [开发计划](./开发计划.md) · [代码审查与验证](./代码审查-2026-10-11.md) · [API 文档](./API.md)

## 产品背景与设计

传统饮食工具需要搜索食物、填写重量和份量，用户看到营养数字后仍难判断下一顿怎么吃。本项目围绕“低成本记录 + 即时行动建议”设计核心流程。

**身体建档 → 生成营养目标 → 记录饮食 → 更新今日进度 → AI 建议 → 用户修正与继续记录。**

| 用户问题 | 产品设计 |
| --- | --- |
| 记录步骤多、难以坚持 | 支持文字、照片和语音转写；单条消息最多 6 张照片，合并理解同一餐。 |
| 不知道今天吃得怎么样 | 展示热量、蛋白质、碳水、脂肪及目标进度，结合资料与今日记录回复。 |
| AI 估算可能不准 | 展示估算或区间，只追问关键信息，允许通过对话和历史餐次直接修正。 |
| 咨询容易被当作记录 | 区分已摄入、计划餐、咨询和修正；服务端校验后才写入，咨询与假设不记餐。 |

## 当前功能

- 首次建档：填写身体信息、目标、训练与日常活动，查看静息代谢、维持消耗和每日营养建议。
- 今日状态：餐食保存、修正或删除后更新营养汇总；系统汇总与模型文字建议分别处理。
- 多模态输入：文字、最多 6 张照片及浏览器语音转写；支持多行输入、流式回复、思考展开、停止与重试。
- 饮食历史：按早餐、午餐、晚餐、加餐管理，支持补记、修改、删除和个人备份。
- 账号与习惯：开放注册、账号数据隔离、明确确认的饮食习惯管理。

## 实现与验证

| 模块 | 实现 |
| --- | --- |
| 前端 | HTML / CSS / JavaScript，桌面及移动布局。 |
| 服务端 | Node.js 24.x，HTTP API 和 SSE 流式响应。 |
| AI | DeepSeek 语言推理与照片联合识别；结构化餐食输出及服务端行为校验。 |
| 云存储 | PostgreSQL + 私有 Vercel Blob，跨实例共享会话、额度、幂等与写入租约。 |
| 本机存储 | SQLite，各账号独立保存资料、餐食、交流与照片。 |
| 部署 | Vercel 云版本；另提供 Docker Compose / systemd 部署模板。 |

已完成从 PRD、交互原型、模型接入到云端上线的 MVP。最近一次审查通过 **66 项本地回归与 13 项临时 PostgreSQL 测试**，覆盖误写入、记录修正、断流重试、账号隔离、照片、备份及事务回滚。测试中的模型与对象存储使用模拟响应，不能代替营养准确率或真实容量评估。

实际手机语音、不同网络下的访问质量、容量压测及站点灾备仍按 [开发计划](./开发计划.md) 验收。语音识别取决于浏览器支持，营养结果是估算值。

## 本地快速开始

使用 Node.js 24.x，在项目目录执行：

```sh
npm ci
cp api-key.example.json api-key.local.json
```

在本机配置文件填入自己的 DeepSeek API Key，再运行 `npm start`，打开 <http://127.0.0.1:3000>。本机配置、环境变量文件、数据库、照片及备份均被 Git 忽略。也可以直接打开 `index.html` 查看前端模拟演示。

云端部署见 [Vercel 部署说明](./VERCEL部署.md)，服务器部署见 [DEPLOY.md](./DEPLOY.md)。以下为各功能的详细使用说明。

## 体验首次建档

直接打开 `index.html`，依次填写身体信息、目标、训练与日常活动程度，即可看到“静息消耗 → 维持消耗 → 每日建议”的计算结果。进入应用后，在「我的计划」查看依据，点击「更新身体信息与目标」可以修改并即时重算。新用户的 Today 与 History 从空记录开始；旧版演示自带的样本餐食会在首次建档时移除，用户自己新增的浏览器记录保留。侧栏的「重新体验建档」会先确认再清空当前浏览器中的记录。

前端会即时预览计划，真实模式由服务端复算、验证并保存计划版本，建档计算本身不需要 API Key。静息消耗采用成人 Mifflin–St Jeor 公式，活动等级对应估算系数，目标调整采用温和规则；蛋白质按体重给出参考值，碳水与脂肪为粗略分配。结果是初始估算，不是实测代谢或个体医疗建议；当前通用流程适用于 18 岁及以上的一般成年人。参考：[原始公式论文](https://pubmed.ncbi.nlm.nih.gov/2305711/)、[NIH 成人体重规划工具及适用范围](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)、[运动人群蛋白质立场文件](https://pubmed.ncbi.nlm.nih.gov/28642676/)。

「我的计划」将静息代谢、所选活动等级下的日常活动与运动增量、全天维持消耗并列展示。增量由维持消耗减去静息消耗得到，已包含在维持消耗中；它不是某一次运动的独立热量估计。当前没有每次运动的时长和强度，因此不单独给出每次训练消耗。

登录本地服务后，打开 <http://127.0.0.1:3000/?preview=1> 可强制使用对话模拟，避免触发 DeepSeek 调用；预览数据不会写进真实账号。去掉 `?preview=1` 才会连接真实记录与模型。

## 语音输入

点击麦克风后会开始识别。浏览器负责将语音识别为文字，页面会显示识别状态和转写内容；自然说完后自动按文字消息发送。若想检查或修改，主动点「结束录音」，再把修改后的文字放入输入框。语音识别本身不调用 DeepSeek，但部分浏览器会使用自己的在线识别服务，需要网络和麦克风权限。

Web Speech 语音识别并非所有浏览器都支持。若内置浏览器提示不支持，可在 Chrome 中打开 `npm start` 显示的本地地址（建议先用 `?preview=1` 测试，不会调用 DeepSeek），允许麦克风后再试。若出现权限、麦克风或网络错误，页面会给出对应提示，并允许改用文字。直接打开 `file://` 页面时，即使对话模拟可用，也不代表内置浏览器提供语音识别。参考：[MDN 浏览器兼容性与在线识别说明](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[MDN 错误类型](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionErrorEvent/error)。

## 启动真实模型模式

打开同目录的 `api-key.local.json`，把 `apiKey` 后面的空字符串改为你的 DeepSeek API Key，并保留两侧的英文双引号。这个文件只供本机服务端读取，已经加入 `.gitignore`，不会提交到 Git。不要把 Key 填进网页或聊天消息。旧配置里的 `model` 字段会被忽略；默认文字使用 DeepSeek V4 Pro，照片先由支持图片的 DeepSeek Flash 识别，再由 V4 Pro 处理。模型与图片能力见 [DeepSeek 模型列表](https://api-docs.deepseek.com/quick_start/pricing/) 和 [Vision 文档](https://api-docs.deepseek.com/guides/vision/)。

例如文件格式如下（示意值不可用）：

```json
{
  "apiKey": "在这里填写你的 Key"
}
```

保存文件后，在终端进入本目录并运行：

```zsh
npm start
```

启动后打开 <http://127.0.0.1:3000>，用户可直接创建账号、登录并建档，无需邀请码，注册人数没有固定上限。用户名为 3–24 位字母、数字或下划线，密码至少 12 个字符。可用 `REGISTRATION_MODE=invite` 切换邀请模式，或 `closed` 暂停普通注册。

若要接管旧 `data/boji.sqlite`，管理员另开终端运行一次 `npm run invite:owner`，在 <http://127.0.0.1:3000/login#invite> 创建站长账号。普通注册不会取得旧资料。仅在启用邀请模式时，用 `npm run invite:member` 生成一次性用户邀请；无需按用户人数修改程序。

修改 Key 或更新服务端代码后，需要在原终端按 `Ctrl+C` 停止旧服务，再运行 `npm start`，最后刷新页面。也可以用 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和 `DEEPSEEK_VISION_MODEL` 环境变量临时覆盖本地配置。项目要求 Node.js 24.x（见 `package.json`）；内置 SQLite 模块启动时可能显示实验性提示。

请用上面的本地服务地址体验真实模型；原来的 `file://` 页面仍是本地模拟回复。两个地址的浏览器存储彼此独立。要迁入旧记录，先在文件版页面的「我的计划」或建档页导出备份，再在服务版选择「导入旧版记录」，可只导入身体资料、只导入饮食与交流或全部导入。旧版演示餐食会标注来源，系统自带样本会跳过；导入前也可先从服务版导出现有备份。

模型回复使用 DeepSeek 的流式 Responses API。等待时显示“模型正在思考”；下拉区域会逐步显示 DeepSeek 本轮实际返回的思考文本。如果本轮没有返回思考文本，页面会如实提示。营养判断和记录为估算，仍应允许用户修正。

## 查看交互

- 说“刚吃了两个鸡蛋”，查看记录和 Today 的更新。
- 问“晚上想吃火锅”，查看不修改 Today 的建议。
- 说“米饭其实只吃了一半”，查看餐次修正。
- 上传餐食照片并补充一句话，查看图片输入。
- 打开「饮食历史」，在早餐、午餐、晚餐、加餐板块查看对话自动记下的食物名称；点击「添加」或某顿的「修改」，填写食物与大致份量后保存。真实模式会用 DeepSeek V4 Pro 重新估算，立即更新当日热量、蛋白质、碳水、脂肪、膳食纤维和目标进度；文件版显示本地模拟估算。
- 在「历史 → 今天的完整交流」查看已完成的交流和模型思考过程；过去日期的餐食也可进入当天页面修改，只更新对应日期。

真实模式的账号和邀请保存在 `data/accounts.sqlite`；站长的旧记录继续放在 `data/boji.sqlite` 与 `data/media/`，普通用户的数据分别放在 `data/users/<账号 ID>/`。这些文件均不提交到 Git。可从「我的计划」导出自己账号的备份、添加或删除长期习惯；聊天中明确说“请记住：我平时喝无糖拿铁”也会保存为习惯。未配置 API Key 时账号资料仍可读取，但模型请求会提示需要配置。默认每人每天最多 30 次模型请求、所有账号合计每天最多 1000 次；可用 `DAILY_MODEL_LIMIT` 和 `GLOBAL_DAILY_MODEL_LIMIT` 调整。AI 并发数、连接缓存和注册策略均可配置，历史按日期分页加载。Docker Compose 与公网部署步骤见 [部署说明](./DEPLOY.md)，本次问题和验证证据见 [代码审查](./代码审查-多人部署.md)。SQLite 服务器模式运行单实例；Vercel 云模式已支持共享 PostgreSQL 与私有 Blob 的多实例访问。容量、真实设备及站点灾备继续按开发计划验收。

如遇到余额提示，可以登录 [DeepSeek 用量页面](https://platform.deepseek.com/usage) 查看账户状态。
